# 常用 UI 组件


| 优先级 | 英文术语 | 常见中文 | 一句话理解 | Agent 验收问题 |
| --- | --- | --- | --- | --- |
| P0 | Button | 按钮 | 触发动作，如保存、发布、删除。 | 文字是否是明确动词；点击后是否有反馈？ |
| P0 | Link | 链接 | 导航到另一个位置或资源。 | 动作使用按钮、导航使用链接，是否混淆？ |
| P0 | Text field / Input | 单行输入框 | 输入短文本，如姓名、邮箱、搜索词。 | 是否有持久标签，而非只靠 Placeholder？ |
| P1 | Textarea | 多行输入框 | 输入较长文本。 | 是否说明长度、格式或示例？ |
| P0 | Select / Dropdown list | 下拉选择 | 从固定选项中选择一个值。 | 选项不多时是否应直接展示？ |
| P1 | Dropdown menu | 下拉菜单 | 点击后显示命令或导航项；与下拉选择不同。 | 用户能否预判菜单里是什么？ |
| P0 | Checkbox | 复选框 | 选择零个、一个或多个独立选项。 | 每项是否可独立成立？ |
| P0 | Radio button | 单选按钮 | 在互斥且可见的选项中选一个。 | 选项是否应同时可见？ |
| P0 | Toggle / Switch | 开关 | 立即切换一个二元状态。 | 若还需提交，是否更适合复选框？ |
| P0 | Tabs | 标签页 | 在同一上下文中切换并列内容。 | 是否并列，还是被误用成流程步骤？ |
| P0 | Accordion | 手风琴折叠区 | 按标题展开或收起内容。 | 是否真的需要隐藏；关键内容是否被折叠？ |
| P0 | Card | 卡片 | 把相关内容和行动组合成视觉单元。 | 内容真的属于独立对象，还是所有东西都卡片化？ |
| P1 | Badge / Tag | 徽标 / 标签 | 显示状态、类别或短属性。 | 颜色之外是否还有文字含义？ |
| P1 | Breadcrumbs | 面包屑 | 显示当前页面在层级结构中的位置。 | 是否反映真实层级，而非浏览历史？ |
| P1 | Pagination | 分页 | 把长结果集分成多页。 | 用户需要定位页码，还是连续加载更合适？ |
| P0 | Modal / Dialog | 模态对话框 | 打断当前页面，要求确认或完成聚焦任务。 | 是否值得打断；关闭、取消和键盘操作是否清楚？ |
| P0 | Drawer | 抽屉 | 从屏幕边缘滑出的面板，常用于导航、筛选或详情。 | 关闭后能否回到原上下文？ |
| P1 | Bottom sheet | 底部面板 | 从移动端底部出现的操作或选择面板。 | 是否适合单手触达，内容是否不过长？ |
| P1 | Popover | 浮层 | 锚定元素显示较丰富的临时内容或操作。 | 点击外部、Esc 和焦点管理是否合理？ |
| P1 | Tooltip | 工具提示 | 悬停或聚焦时显示简短补充说明。 | 关键说明不能只放这里；触屏如何访问？ |
| P0 | Toast / Snackbar | 轻提示 | 短暂显示操作结果，不阻塞当前任务。 | 重要或需处理的信息是否不应自动消失？ |
| P0 | Alert / Banner | 警告 / 通知横幅 | 持续展示重要状态、风险或全局信息。 | 严重级别、影响范围和下一步是否明确？ |
| P0 | Table / Data table | 表格 / 数据表 | 以行列比较数据；数据表常含排序、筛选和批量操作。 | 移动端如何处理，主列是否清楚？ |
| P0 | Search box | 搜索框 | 通过关键词定位内容或对象。 | 范围、示例和无结果反馈是否清楚？ |
| P0 | Filter | 筛选器 | 缩小结果集合。 | 当前条件是否可见、可清除？ |
| P1 | Date picker | 日期选择器 | 选择日期或日期范围。 | 是否允许键盘输入并明确格式？ |
| P0 | Stepper / Wizard | 分步流程 | 把复杂任务拆成有顺序的步骤。 | 步骤是否真有依赖；返回是否丢数据？ |
| P1 | Progress bar | 进度条 | 显示可估算任务的完成比例。 | 进度是否真实；无法估算时不要伪造百分比。 |
| P0 | Spinner | 加载转圈 | 表示系统正在处理，但不展示内容结构。 | 等待较长时是否提供原因、进度或取消？ |
| P0 | Skeleton screen | 骨架屏 | 加载时用占位形状预示即将出现的布局。 | 形状是否接近真实内容，避免无意义闪烁？ |
| P1 | Carousel | 轮播 | 在有限区域轮换多项内容。 | 用户是否会错过自动轮换内容；是否真需要？ |

组件是可复用的单个 UI 部件；模式则是为某类用户任务组织多个组件的解决方案。GOV.UK Design System 将 Components 定义为可复用界面部分，将 Patterns 定义为面向具体用户任务和页面类型的最佳实践方案。[^G1][^G2]
