# 交互与状态术语


| 优先级 | 英文术语 | 常见中文 | 一句话理解 | Agent 验收问题 |
| --- | --- | --- | --- | --- |
| P0 | Default state | 默认状态 | 用户尚未交互时的正常外观。 | 是否能看出哪些元素可操作？ |
| P1 | Hover state | 悬停状态 | 鼠标停留时的反馈。 | 不能把关键信息只放在 Hover，因为触屏没有。 |
| P0 | Focus state | 焦点状态 | 键盘或辅助设备当前定位元素的可见提示。 | 按 Tab 是否始终知道自己在哪里？ |
| P0 | Pressed / Active state | 按下状态 | 按键正在被按下时的即时反馈。 | 点击是否有明确的“已接收”感觉？ |
| P0 | Selected state | 选中状态 | 表示某项已被选择。 | 是否同时用形状、图标或文字，而非只靠颜色？ |
| P0 | Disabled state | 禁用状态 | 当前不可操作的状态。 | 能否解释为何不可用以及如何变为可用？ |
| P0 | Loading state | 加载状态 | 数据或操作尚未完成。 | 是否防止重复提交，并说明系统仍在工作？ |
| P0 | Empty state | 空状态 | 没有数据、结果或内容时的页面。 | 是否区分首次使用、无搜索结果和数据被清空？ |
| P0 | Success state | 成功状态 | 确认任务已完成。 | 是否说明发生了什么和下一步？ |
| P0 | Error state | 错误状态 | 系统或输入失败时的反馈。 | 是否说明问题位置、原因和修复方法？ |
| P0 | Validation | 输入校验 | 检查用户输入是否满足要求。 | 是否尽早、就地提示，而非只给模糊总错误？ |
| P1 | Permission denied | 无权限状态 | 用户无权查看或执行操作。 | 是否区分未登录、权限不足和资源不存在？ |
| P1 | Offline state | 离线状态 | 网络不可用或连接中断。 | 是否说明哪些内容仍可用、何时重试？ |
| P0 | Destructive action | 破坏性操作 | 可能造成不可逆损失的操作，如永久删除。 | 是否视觉区分、二次确认或提供撤销？ |
| P0 | Confirmation | 确认 | 在高风险或重要操作前后确认意图或结果。 | 是否只在真正高风险时使用，避免确认疲劳？ |
| P1 | Undo | 撤销 | 操作后允许在短时间内恢复。 | 能撤销时，是否比频繁弹确认框更顺畅？ |
| P0 | System feedback | 系统反馈 | 系统对用户行为的状态回应。 | 每次关键操作是否说明已接收、处理中或完成？ |
| P1 | Microinteraction | 微交互 | 围绕单个动作的细小反馈与状态变化。 | 是否提高理解，而不是只增加可爱动画？ |
| P1 | Transition | 过渡动画 | 界面从一个状态到另一个状态的连续变化。 | 是否帮助解释空间或状态关系？ |
| P1 | Scroll-triggered motion | 滚动触发动画 | 滚动到某处时出现的动效。 | 是否影响阅读、性能或让内容延迟出现？ |
| P0 | Reduced motion | 减少动态效果 | 尊重用户减少动画的系统偏好。 | 关闭大幅动画后关键功能是否仍完整？ |

> **Agent 生成界面的常见缺陷不是“默认状态不好看”，而是根本没有设计其他状态。**  对任何会读写数据的界面，至少检查：默认、加载、空、成功、错误、禁用、无权限；涉及网络时再检查离线和重试。
