# UX、流程、设计系统、响应式与无障碍


| 优先级 | 英文术语 | 常见中文 | 一句话理解 | Agent 验收问题 |
| --- | --- | --- | --- | --- |
| P0 | UX (User Experience) | 用户体验 | 用户与产品、服务和组织交互的整体体验；UI 只是其中一部分。 | 是否只讨论好不好看，却忽略任务是否顺利？ |
| P0 | UI (User Interface) | 用户界面 | 用户看见并操作的界面元素与布局。 | 界面是否清楚表达系统能力和状态？ |
| P0 | Usability | 可用性 | 用户能否有效、较高效且少出错地完成任务。 | 新用户能否无需解释完成核心任务？ |
| P0 | Information architecture (IA) | 信息架构 | 组织、命名内容并建立关系，使其可查找、可理解。 | 分组和命名是否符合用户语言？ |
| P1 | Sitemap | 站点地图 | 把网站页面及层级画出的规划视图；不是 IA 的全部。 | 是否只画页面树，却没处理命名和跨页关系？ |
| P0 | User flow | 用户流 | 用户从入口到目标的整体路径，可含多个页面和分支。 | 是否覆盖成功、退出和失败分支？ |
| P0 | Task flow | 任务流 | 完成一个具体任务的步骤序列。 | 是否有不必要步骤或重复输入？ |
| P0 | Wireframe | 线框图 | 低细节页面草图，强调内容、布局和优先级。 | 是否在视觉装饰前先解决结构？ |
| P1 | Wireflow | 线框流程图 | 把线框图与流程箭头结合，展示每一步界面变化。 | 动态应用是否遗漏反馈和状态？ |
| P1 | Mockup | 高保真静态稿 | 接近成品视觉的静态界面图。 | 不要把静态漂亮误认为交互完整。 |
| P1 | Prototype | 原型 | 可模拟点击、流程或状态变化的设计模型。 | 是否验证了最关键的不确定性？ |
| P1 | Fidelity | 保真度 | 设计稿接近成品的程度。 | 当前阶段是否用了合适精度，避免过早精修？ |
| P0 | Design system | 设计系统 | 用于规模化管理设计的一套标准、组件、模式、内容和治理机制。 | 项目规模是否真需要完整系统？ |
| P1 | Style guide | 样式指南 | 颜色、字体、品牌、内容语气和视觉规则。 | 规则是否能指导实际界面？ |
| P0 | Component library | 组件库 | 可复用的单个 UI 元素及其属性、状态和用法。 | 是否包含状态与使用说明，而不只是外观？ |
| P1 | Pattern library | 模式库 | 可复用的组件组合、布局或任务解决方案。 | 是否解释适用场景，而非只提供模板？ |
| P1 | Design tokens | 设计令牌 | 把颜色、字号、间距、圆角等决策命名为可复用变量。 | Agent 是否从同一组规则派生视觉？ |
| P1 | Affordance | 可供性 | 元素本身让用户感知到可以如何操作。 | 按钮看起来像能点，输入框像能输入吗？ |
| P1 | Signifier | 操作线索 | 明确提示可操作方式的视觉或文字线索。 | 是否需要标签、图标、边框或文案帮助理解？ |
| P0 | Discoverability | 可发现性 | 用户能否意识到某功能或内容存在。 | 重要功能是否藏在陌生图标或多层菜单？ |
| P0 | Findability | 可查找性 | 用户知道要找什么时，能否顺利找到。 | 搜索、导航和命名是否支持明确目标？ |
| P0 | Mental model | 心智模型 | 用户对系统如何工作的已有理解。 | 是否遵循惯例，或清楚解释偏离？ |
| P0 | Cognitive load | 认知负荷 | 用户为理解、记忆和决策付出的脑力。 | 是否一次要求理解太多概念或选项？ |
| P0 | Friction | 操作摩擦 | 阻碍前进的额外步骤、疑虑或成本。 | 摩擦是否必要；能否减少不必要部分？ |
| P1 | Conversion | 转化 | 用户完成目标行为，如注册、购买、预约。 | 优化转化是否仍尊重知情与选择？ |
| P0 | User goal | 用户目标 | 用户来到产品真正想完成的事。 | 页面是否围绕用户任务，而非组织结构？ |
| P0 | Page's single job | 页面唯一主任务 | 这个页面最应该帮助用户完成的一件事。 | 能否用一句动词短语说清？ |
| P0 | Progressive disclosure | 渐进披露 | 先展示必要信息，需要时再展开高级细节。 | 是否减少初始复杂度，又不隐藏关键内容？ |
| P0 | Recognition over recall | 识别优于回忆 | 让选项和上下文可见，少要求用户记住信息。 | 是否必须记住上一页内容或神秘命令？ |
| P0 | Responsive design | 响应式设计 | 让页面在不同屏幕和设备上重新布局并保持可用。 | 移动端是否重组，而非把桌面版缩小？ |
| P1 | Viewport | 视口 | 用户当前可见的浏览器区域。 | 是否适应不同视口，而非假设固定画布？ |
| P1 | Breakpoint | 断点 | 布局在内容不再适配时切换规则的阈值。 | 是否按内容需要调整，而非盲从设备清单？ |
| P1 | Mobile-first | 移动优先 | 先解决小屏内容优先级，再增强大屏。 | 移动端是否保留核心任务？ |
| P0 | Reflow | 内容重排 | 屏幕变窄时内容换行、堆叠、移动或改变顺序。 | 是否出现横向滚动、挤压或顺序错误？ |
| P0 | Touch target | 触控目标 | 用户手指可点击的实际区域。 | 按钮、图标和列表项是否够大且有间隔？ |
| P0 | Keyboard navigation | 键盘导航 | 不用鼠标也能访问和操作界面。 | Tab、Enter/Space、Esc 是否符合预期？ |
| P0 | Focus indicator | 焦点指示 | 显示键盘当前所在控件的视觉标记。 | 焦点是否清楚可见且未被移除？ |
| P0 | Color contrast | 颜色对比度 | 前景与背景的可辨识差异。 | 正文、控件边界和状态是否易辨认？ |
| P0 | Alt text | 替代文本 | 为有信息意义的图片提供文字等价描述。 | 装饰图是否忽略，功能图是否说明目的？ |
| P0 | Label | 标签 | 明确说明输入、控件或数据的名称。 | 是否持久可见并靠近对应元素？ |
| P1 | Screen reader | 屏幕阅读器 | 把界面结构与内容转为语音或其他输出的辅助技术。 | 页面结构和控件名称能否被正确理解？ |
| P1 | Localization | 本地化 | 让语言、格式、长度和文化表达适应地区。 | 中英文长度变化后布局是否仍成立？ |
| P0 | UX writing | 用户体验写作 | 为导航、按钮、提示、错误和帮助写清楚可行动的文字。 | 文字是否帮助任务，而非只营造情绪？ |
| P0 | Microcopy | 微文案 | 按钮、标签、提示、错误等短界面文字。 | 是否具体、一致、使用主动语态？ |
| P0 | Placeholder | 占位提示 | 输入框内部的临时示例，输入后通常消失。 | 是否误把它当成唯一标签？ |
| P0 | Helper text | 辅助说明 | 在控件附近解释格式、用途或限制。 | 是否在用户出错前提供必要信息？ |
| P0 | Tone and voice | 语气与品牌声音 | 产品长期一致的表达方式及不同场景的语气调整。 | 错误、成功和营销文案是否像同一产品？ |

信息架构负责内容的组织、关系、命名和导航，其目标包括可查找性与可发现性；Sitemap 只是表达页面结构的一种规划视图，不等于完整信息架构。[^N6]

Wireflow 把页面级线框图与流程图结合，适合说明动态应用中用户操作后同一页面如何变化。[^N10]

响应式设计是一种让页面在不同屏幕尺寸和分辨率上保持良好呈现与可用性的设计方法，不是一项单独技术，也不是把桌面页面等比例缩小。[^M1]
